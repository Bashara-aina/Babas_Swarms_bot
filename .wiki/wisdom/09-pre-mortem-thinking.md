# Pre-Mortem Thinking — Kill It Before It Fails

Source: Gary Klein research + Shane Parrish (Farnam Street) + Decision Stack 2026

## What It Is
Post-mortem: analyze why something failed AFTER it failed.
Pre-mortem: imagine it's 1 year from now, the project FAILED.
Now work backwards: what went wrong?

This is inversion applied to project planning.

## The Pre-Mortem Protocol
Before starting any significant project/feature:
1. "Imagine it's 12 months from now. This failed completely."
2. "What are the 5 most likely reasons it failed?"
3. "Which of these is most likely? Most catastrophic?"
4. "What would we do differently knowing this?"

LEGION RULE: For any project Bashara is planning,
run a pre-mortem before endorsing the plan.

## The Kill Criteria
Define in advance: "We will stop this project if [X] happens."
Most teams never define kill criteria → zombie projects consume resources forever.

LEGION RULE: For any ongoing project, ask:
"What would have to be true for us to STOP this?"
If Bashara can't answer → help define it.

## Applied to Legion's Own Development
Pre-mortem for Legion bot:
"It's 2027. Legion bot failed to become useful. Why?"
- No one trusted it because it was wrong too often
- It became too complex to maintain
- It cost too much to run
- Bashara stopped developing it when thesis got hard
Kill criteria: if 3+ consecutive days pass with zero meaningful use → audit why.
