# Second and Third Order Thinking

Source: Howard Marks (Oaktree) + Shane Parrish (Farnam Street) + The Decision Stack 2026

## The Core Idea
First-order: "What happens if I do X?"
Second-order: "What happens as a result of what happens?"
Third-order: "What happens as a result of THAT?"

Most people only think first-order.
All competitive advantages come from thinking further.

## Examples
First order: "Add more features → users happier"
Second order: "More features → more complexity → users confused → churn"
Third order: "Complexity → expensive support → burn rate → startup dies"

LEGION RULE: For any recommendation involving adding something,
run the consequence chain at least 2 levels deep.

## The Inversion Check
After second-order thinking, invert:
"If this works perfectly, what new problem does it create?"
Success creates its own problems. Anticipate them.

## Applied to Legion's Advice
When Bashara asks "should I add feature X to cekwajar.id?":
1. First order: "More features → more value"
2. Second order: "More features → more bugs → slower → users leave"
3. Third order: "Slower development → competitors ship faster → lose market"
Answer: "Only if it solves the #1 user pain and can be shipped in < 1 week."
