# ADR-015: Response Quality Gate

**Date**: 2026-04-12  
**Status**: Accepted  
**Priority**: 6 (Depth Upgrade)

## Context

Currently, if the LLM returns a shallow, vague, or wrong answer, it gets sent to the user immediately. There's no system-level check on response quality before sending.

This creates a gap where:
- Complex questions get short shallow answers (e.g., "I don't know" to a 30-word technical question)
- Explicit uncertainty signals aren't caught (e.g., "I'm not sure" without triggering search)
- LLM identity artifacts (e.g., "As an AI...", "I cannot...") can slip through

## Decision

Create `core/quality_gate.py` — a post-response quality inspector that evaluates every LLM response against known failure patterns before returning it to the user.

### Quality Gates

1. **SHALLOW**: If user message >20 words AND response <30 words → flag as shallow
2. **UNCERTAIN**: If response contains uncertainty signals without "search/web" keyword → flag as uncertain  
3. **ARTIFACT**: If response contains forbidden LLM identity phrases → flag as artifact

### Retry Behavior

- MAX_RETRIES = 1 (never retry more than once — latency matters)
- On any flag: retry with explicit instruction to fix the issues
- Retry adds a system message: "Your previous response had these issues: X, Y, Z. Fix them. Be concrete, specific and stay in Legion's voice."

## Implementation

**File**: `core/quality_gate.py`

```python
@dataclass
class QualityResult:
    issues: list[str]
    should_retry: bool

class QualityGate:
    UNCERTAINTY_SIGNALS = ["I don't know", "I'm not sure", "gw ga tau", ...]
    FORBIDDEN_ARTIFACTS = ["As an AI", "I cannot", "I'm unable to", ...]
    
    async def check(self, user_message, response, intent) -> QualityResult
    async def retry(self, messages, issues) -> str
```

**Wiring**: In `llm_client/__init__.py` after LLM response is generated, before returning to caller:

```python
_qg = QualityGate()
_quality = await _qg.check(task, result, agent_key or "general")
if _quality.should_retry:
    logger.info("Quality gate triggered: %s", _quality.issues)
    result = await _qg.retry(messages, _quality.issues)
```

## Consequences

**Positive**:
- No more shallow one-liners to complex technical questions
- Uncertainty is flagged and triggers retry instead of being sent
- LLM identity artifacts are caught before user sees them

**Negative**:
- One additional LLM call on retry (max), adding ~500-800ms latency on flagged responses
- Retry count is capped at 1 to prevent latency spiral
