# ADR-019: Context Window Budget Management

**Date**: 2026-04-12  
**Status**: Implemented  
**Priority**: 10 (Legion Depth Upgrade)

## Context

All 13 prompt injection layers were concatenated linearly with no priority pruning or compression. A 1500+ token memory block accumulated per turn when all layers were full, with no token budget management.

## Decision

Implement priority-based token budget management in `core/system_prompt_builder.py` that:

1. Uses max 35% of model's context window for system prompt (configurable via `CONTEXT_BUDGET_RATIO`)
2. Defines priority order (highest to lowest): soul → user_profile → working_memory → relevant_memory → wiki_context → search_results → personality → skill_context
3. Soul is **ALWAYS first and NEVER compressed**
4. Adds token counting via rough estimate (`len(text) // 4`)
5. Compresses lower-priority layers when budget is tight (target 200 tokens)
6. Skips layers that still don't fit after compression

## Constants Added

```python
MODEL_CONTEXT_LIMITS = {
    "default": 16000,
    "gpt-4o": 128000,
    "claude-3-5-haiku": 200000,
}
CONTEXT_BUDGET_RATIO = 0.35
LAYER_PRIORITY = [
    "soul",           # ALWAYS included, never compressed
    "user_profile",   # ALWAYS included (top 5 facts only)
    "working_memory", # Last 5 exchanges, compressed if tight
    "relevant_memory",# Top-3 semantic results, dropped if very tight
    "wiki_context",   # Only if directly relevant to query
    "search_results", # Only if search was triggered
    "personality",    # Compressed to key traits if tight
    "skill_context",  # Only if skill was triggered
]
```

## New Functions

- `estimate_tokens(text)` — rough token estimate using `len(text) // 4`
- `compress_section(content, target_tokens)` — truncates middle of content
- `_get_*_content()` — per-layer async fetchers
- `get_layer_content(layer_name, user_id, query, extras)` — dispatcher
- `build_system_prompt(user_id, query, model, extras)` — main async builder

## Verification

- `python scripts/verify_wiring.py` passes all 7 tests
- `build_system_prompt()` correctly budgets tokens
- Soul is always first when present
- Log line appears for each build: `"System prompt build: {used}/{budget} tokens, {sections}/{layers} layers"`

## Consequences

- System prompts stay within configured budget
- Lower-priority layers gracefully drop when context is tight
- Soul and user profile are always preserved
- Backward compatibility maintained via existing `build_full_system_prompt()` and `SystemPromptBuilder` class
