# ADR-014: Clarifying Questions on Low-Confidence Intent

## Status
Accepted — 2026-04-12

## Context
When Legion's intent confidence falls below 0.4 AND the user message is short (< 8 words),
the system was defaulting to `casual_chat` — producing generic, thoughtless responses.
This made Legion feel dumb rather than helpful.

## Decision
Create `core/clarification.py` with two async functions:
- `should_clarify(message, intent, confidence)` — returns `True` when:
  - `confidence < 0.4` AND
  - `word_count < 8` AND
  - message is NOT in the `NEVER_CLARIFY` set (greetings, courtesies)
- `generate_clarification(message, intent)` — returns ONE specific question, no lists, no fluff

Wire `ask_if_needed()` into `handlers/message_handler.py` as a pre-fallback intercept
in `handle_plain_message()`. It fires AFTER `skill_match` is obtained but BEFORE
the generic `chat` fallback, so ambiguous short messages get a clarifying question
instead of a generic LLM response.

## Logic
```python
AMBIGUITY_THRESHOLD = 0.4
SHORT_MESSAGE_THRESHOLD = 8

NEVER_CLARIFY = {"hei", "hai", "hi", "hello", "oke", "ok", "thanks", ...}
```

Question generation is rule-based (no LLM call needed) with intent-specific patterns:
- `fix this` → "Fix what exactly? Paste the code or error."
- `translate` → "Translate what, and to which language?"
- `analisis sistem` → "Analisis sistem yang mana? Beri nama sistem atau detail spesifik."

## Consequences
- Ambiguous short messages get specific follow-up questions instead of generic answers
- Legitimate greetings ("Hei") still work normally
- Longer messages (>8 words) always proceed normally regardless of confidence
- No new LLM call needed — rule-based generation is fast and deterministic
