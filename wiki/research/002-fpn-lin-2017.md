# Feature Pyramid Networks for Object Detection (FPN)

**Authors:** Tsung-Yi Lin, Piotr Dollár, Ross Girshick, Kaiming He, Bharath Hariharan, Serge Belongie
**Year:** 2017
**Venue:** CVPR
**ArXiv/DOI:** [arXiv:1612.03144](https://arxiv.org/abs/1612.03144)
**Citation count:** ~45,000+
**Relevance to POPW:** POPW's neck IS an FPN. Every detection, pose, and activity decision uses FPN's multi-scale features. The lateral 1×1 convs and top-down pathway are directly implemented in `model.py:FPN`.

## Core Contribution

Standard feature pyramids (图像金字塔) were computationally expensive for deep networks. FPN shows that a ConvNet's feature hierarchy can be converted into a fast multi-scale pyramid WITHOUT the computational cost of processing each scale independently. The key insight: combine low-resolution semantically-strong features with high-resolution semantically-weak features via top-down pathway + lateral connections.

## Key Technical Details

- **Two pathways**:
  1. **Bottom-up pathway** (standard ConvNet forward — ResNet's C3, C4, C5 at strides 8, 16, 32)
  2. **Top-down pathway** (coarse features upsampled 2× + lateral connection)
- **Lateral connection**: 1×1 conv from bottom-up to reduce channels to 256 (for all levels)
- **Smooth convolution**: 3×3 conv after each merged level to reduce aliasing from upsampling
- **Output levels**: P2, P3, P4, P5, P6, P7 (P6 = C5 with stride-2 conv, P7 = P6 with stride-2 conv)
- **All outputs 256 channels** — uniform channel count for all detection heads
- **P2-P5 used for anchor-based detection** (P2 is highest resolution, P5 lowest)
- **P6-P7 used only for large objects** (in original FPN; POPW uses P3-P7 for anchors)

## Results They Achieved

| Method | COCO mAP@0.5 | FPS |
|--------|-------------|-----|
| FPN w/ Faster R-CNN (ResNet-50) | 59.1% | 5.5 |
| FPN w/ RetinaNet (ResNet-101) | 60.0% | 5.3 |
| Without FPN (ResNet-101, conv5 only) | 44.0% | 12 |

## What POPW Can Steal Directly

1. **Lateral connection exact design** (`model.py:37-50`): `nn.Conv2d(in_channels, 256, 1)` for C3→P3, C4→P4, C5→P5. 1×1 conv to reduce channel dimension.
2. **Top-down upsampling** (`model.py:53-54`): `F.interpolate(p5, size=c4.shape[2:], mode='nearest')` then `p4 = lateral_c4(c4) + upsampled_p5`.
3. **P6/P7 construction** (`model.py:55-57`): `p6_conv = nn.Conv2d(C5, 256, 3, stride=2)` and `p7_conv = nn.Conv2d(p6, 256, 3, stride=2)`. These are for large object detection.
4. **Smooth conv after merge** (`model.py:55-57`): The 3×3 conv after each level reduces aliasing artifacts from upsampling.

## Failure Modes / Limitations

- **Semantic gap at fine resolutions**: P2 (highest resolution) has weak semantics because top-down signal degrades through multiple upsampling steps. Solutions: PANet (bottom-up augmentation), HRNet (maintain high-res throughout).
- **Fixed 256 channels may be suboptimal**: Some papers show 128 or 512 channels works better for specific tasks. POPW uses 256 (fixed).
- **Memory cost of P2**: P2 has 4× the pixels of P3, 16× of P5. On POPW's 640×480 images, P2 feature maps are 80×60 = 4800 locations × 9 anchors = 43K anchors. Most are negative (background), causing class imbalance.
- **Small objects hurt most**: FPN helps large objects most; small objects (assembly parts are small!) benefit least from FPN alone.

## Key Equations

**Lateral connection merge:**
```
P_n = Conv_1×1(C_n) + Upsample_2×(P_{n+1})
```
where `P_n` is the output pyramid level, `C_n` is the corresponding bottom-up level.

**Smooth convolution (post-merge):**
```
P_n_out = Conv_3×3(P_n)  # reduces aliasing from upsampling
```

## Implementation Notes

```python
# FPN implementation (from model.py:37-64)
class FPN(nn.Module):
    def __init__(self, in_channels_list=[512, 1024, 2048], out_channels=256):
        super().__init__()
        # Lateral 1×1 convs to reduce to 256 channels
        self.lateral_c3 = nn.Conv2d(in_channels_list[0], out_channels, 1)
        self.lateral_c4 = nn.Conv2d(in_channels_list[1], out_channels, 1)
        self.lateral_c5 = nn.Conv2d(in_channels_list[2], out_channels, 1)
        # Smooth 3×3 after merge
        self.smooth_p3 = nn.Conv2d(out_channels, out_channels, 3, padding=1)
        self.smooth_p4 = nn.Conv2d(out_channels, out_channels, 3, padding=1)
        self.smooth_p5 = nn.Conv2d(out_channels, out_channels, 3, padding=1)
        # P6, P7 from C5
        self.p6_conv = nn.Conv2d(in_channels_list[2], out_channels, 3, stride=2, padding=1)
        self.p7_conv = nn.Conv2d(out_channels, out_channels, 3, stride=2, padding=1)

    def forward(self, c3, c4, c5):
        p5 = self.lateral_c5(c5)
        p4 = self.lateral_c4(c4) + F.interpolate(p5, size=c4.shape[2:], mode='nearest')
        p3 = self.lateral_c3(c3) + F.interpolate(p4, size=c3.shape[2:], mode='nearest')
        p3 = self.smooth_p3(p3)
        p4 = self.smooth_p4(p4)
        p5 = self.smooth_p5(p5)
        p6 = self.p6_conv(c5)
        p7 = self.p7_conv(F.relu(p6))
        return {'p3': p3, 'p4': p4, 'p5': p5, 'p6': p6, 'p7': p7}
```

**Gotcha**: In POPW, FPN is applied to C3 (stride 8), C4 (stride 16), C5 (stride 32). This matches the paper. However, P3 (from C3) is the highest resolution used for detection — this is important for small furniture parts.

## LEGION RULE

When Bashara asks about "why does the detection head get P3-P7 and not just C5," reference this paper's finding: FPN's top-down pathway transfers semantic information from coarse (P5) to fine (P3) scales. P3 has high spatial resolution (important for small parts) combined with strong semantics (from top-down). C5 alone has strong semantics but low resolution (1/32 of image = 20×15 for 640×480).

Applied to POPW: The 7 furniture part classes (legs, panels, shelves) are small relative to the image. P3 (stride 8 = 80×60) is the most important FPN level for detection. If leg parts are only 40×10 pixels, they need P3's resolution to generate enough anchor locations.
