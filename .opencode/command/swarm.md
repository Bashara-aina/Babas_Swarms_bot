Orchestrate multiple specialized agents to work on different aspects of a complex task.

## How /swarm Works

Route by task complexity:

### Simple Tasks (1-2 steps, single file)
→ Direct agent calls (current implementation)
→ Use when: single file, clear path, no research needed

### Medium Tasks (3-5 steps, multiple files or domains)
→ LangGraph stateful graph with checkpointing
→ Use when: multi-file, needs state tracking, may be interrupted
```python
from core.integrations.langgraph_orchestrator import LangGraphAgent
agent = LangGraphAgent(config=LangGraphConfig(graph_type="plan_execute", max_steps=15))
# Checkpointer saves to ~/.legion/langgraph_checkpoints/
from langgraph.checkpoint.memory import MemorySaver
checkpointer = MemorySaver()
```

### Complex Tasks (6+ steps, multiple domains or teams)
→ CrewAI with specialist agents
→ Use when: multi-domain research, cross-team coordination
```python
from core.integrations.crewai_orchestrator import SwarmBotCrew
crew = SwarmBotCrew(verbose=True)
crew.add_agent("researcher", "Research latest trends")
crew.add_agent("writer", "Summarize findings")
result = await crew.kickoff("<task>")
```

### Auto-Detection
- If task contains: "research", "analyze", "compare" → CrewAI
- If task contains: "implement", "fix", "build" + multiple files → LangGraph
- Otherwise → Direct agent calls

## Complexity Detection Examples
| Keywords | Route |
|----------|-------|
| research, analyze, compare, evaluate | CrewAI |
| implement, build, create, add feature | LangGraph |
| fix, refactor, rename, move | Direct |

## Workflow
1. **Planner** decomposes task, detects complexity, routes appropriately
2. **Worker** agents execute subtasks in parallel (LangGraph) or sequence (CrewAI)
3. **Reviewer** checks each subtask
4. **Planner** synthesizes and integrates
5. **@wikibot** writes session summary to mem0 after completion

## RUFLO Task Lifecycle (wire every task)

For each contract generated by planner:
1. `ruflo_task_create(title=<contract>, assignee=worker)` — register task
2. `ruflo_task_status(task_id)` — track completion
3. `ruflo_worker_dispatch(worker_name, task_id)` — assign to agent

On swarm completion:
1. `ruflo_session_save(name=<task>, include_memory=true)` — persist session
2. `mem0_add(user_id=bashara, content=<session_summary>, metadata={agent: wikibot, task: <task>, outcome: success})`
3. `ruflo_neural_train(data=<successful_patterns>, pattern_type=task)` — weekly

## Swarm-Bot Agent System
- **@planner** — task decomposition, never edits files
- **@worker** — executes code changes
- **@reviewer** — reviews before commit
- **@wikibot** — writes session summaries to .wiki/ and mem0

## Coordination
- Agents communicate via shared context
- Planner tracks progress via ruflo_task_status
- Reviewer approves before next step

## Constraints
- Task must be complex enough to warrant multiple agents
- Clear role separation required
- Planner stays in control
- Max 25 contracts per swarm run (split if more needed)

## When NOT to Use /swarm
- Simple, single-file changes
- Tasks under 30 minutes
- When a single agent can handle it
