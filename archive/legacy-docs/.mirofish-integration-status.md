## Known limitations
- **Simulation requires project**: MiroFish `/simulation/create` requires a pre-built `project_id` with a Zep knowledge graph. Topic-based ad-hoc simulation uses MiniMax LLM fallback (configured via `MINIMAX_API_KEY`).
- **DDGS rate-limits news**: `duckduckgo_search` rate-limits under heavy use → news fetch may return 0 articles. Acceptable for MVP; consider Exa/Tavily for production.
- **yfinance rate limit**: ~2000 req/day free. No caching layer yet.
- **LLM fallback timeout**: `create_structured_completion` may return empty responses if MiniMax API key is invalid/rate-limited. `_llm_market_simulation` has 45s timeout.
- **Submodule read-only**: `tools/mirofish` push denied (no write access to `666ghj/MiroFish`). Python 3.11 fixes are local only.
- IDX market hours: 09:00–15:30 WIB (Mon–Fri). Heavy simulations for off-hours only.

## Error handling chain
```
run_full_simulation(topic)
  └─> POST /api/simulation/create {project_id: "legion_market"}
        ├─ 200 OK → simulation created
        ├─ 404/400 (project not found) → _fallback=True
        │     └─> _llm_market_simulation(topic, rounds)
        │           ├─ create_structured_completion (45s timeout)
        │           ├─ success → {narrative, confidence, source}
        │           └─ timeout/error → {error: "Simulation unavailable: ..."}
        └─ network error → _call_mirofish_direct (requires prepared simulation config)
```
