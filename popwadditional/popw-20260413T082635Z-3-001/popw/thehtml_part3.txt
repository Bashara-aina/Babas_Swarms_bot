<h3>8a. The Problem of Fixed Loss Weights</h3>
<p>The naive approach: $\mathcal{L}_{\text{total}} = \lambda_1 \mathcal{L}_{\text{det}} + \lambda_2 \mathcal{L}_{\text{pose}} + \lambda_3 \mathcal{L}_{\text{act}}$</p>
<p>This fails because Wing Loss values live in normalized coordinate space (often <strong>0.02 to 0.12</strong> early in training), Focal terms sit in log-probability space (often <strong>0.4 to 3.2</strong>), and CB-Focal scales with per-class weights. These are on <strong>completely different scales</strong>. Changing any hyperparameter requires re-tuning all three λ values.</p>

  <p style="font-size:0.8rem;color:var(--text-faint);margin:8px 0 0;">Without Kendall, naive sum is dominated by Wing-scale terms. Kendall reweights by learned uncertainty.</p>
</div>

<div id="kendallWithoutPanel" class="without-method-panel" hidden>
<p>With fixed λ, whichever raw loss has the largest magnitude dominates the backward pass: detection Focal+Smooth-L1 can be <strong>10–50×</strong> larger than Wing in unit space, so activity gradients vanish unless λ is hand-retuned after every change to batch size, augmentation, or class prior. Kendall learns a precision per task so each $\mathcal{L}_t$ contributes at a comparable effective scale without a manual grid search.</p>
</div>

<h3>8b. Kendall's Solution (Log-Parameterization)</h3>
$$\mathcal{L}_{\text{total}} = \sum_t \left[ e^{-s_t} \cdot \mathcal{L}_t + s_t \right]$$

<p>where $s_t = \text{clamp}(\log\sigma_t^2, -4.0, 2.0)$ are <strong>learnable parameters</strong>.</p>

<div class="card card-accent">
<h4 style="margin-top:0">Why optimize $s = \log\sigma^2$ instead of $\sigma$ or $\sigma^2$?</h4>
<p style="font-size:0.88rem;margin-bottom:0">If you parameterize the precision directly as $1/\sigma^2$, a small $\sigma$ explodes the weight and causes numerical blow-ups. If you learn $\sigma^2$ directly, the optimizer can push $\sigma^2 \to 0$, again sending precision to infinity and producing <strong>NaNs</strong>. Writing $s = \log\sigma^2$ makes the effective multiplier $e^{-s} = 1/\sigma^2$ always <strong>positive</strong>, and gradients with respect to $s$ are stable. Our implementation <strong>clamps</strong> $s$ to $[-4, 2]$, bounding task weights to a sane range (see table below).</p>
</div>

<p>Expanding for our three tasks:</p>
$$\mathcal{L}_{\text{total}} = e^{-s_d} \cdot \mathcal{L}_{\text{det}} + s_d + e^{-s_p} \cdot \mathcal{L}_{\text{pose}} + s_p + e^{-s_a} \cdot \mathcal{L}_{\text{act}} + s_a$$

<h3>8e. Self-Balancing Mechanism</h3>
<p>The term $e^{-s_t}$ acts as precision (inverse variance) — the task weight. The regularization term $+s_t$ prevents the optimizer from simply increasing all $s_t$ to infinity (which would trivially minimize all task contributions to zero). When a task has high loss, its gradient pushes $s_t$ negative → $e^{-s_t}$ increases → more weight → faster convergence. When a task converges, $s_t$ drifts positive → weight decreases → capacity shifts to underperforming tasks.</p>

<h3>8g. Professor Questions</h3>
<div class="card" style="padding:0;overflow:hidden">
  <button class="accordion-toggle" onclick="toggleAccordion(this)">
    <span>Q: "Why not just tune λ manually?"</span><span class="accordion-arrow">▸</span>
  </button>
  <div class="accordion-body">
    <p>Three losses on completely different scales: Wing loss produces values typically <strong>0.02–0.12</strong>, Focal terms <strong>0.4–3.2</strong>, and CB-Focal depends heavily on the per-class weights. Manual tuning requires grid search over 3+ dimensions — and must be repeated whenever <em>any</em> hyperparameter changes (learning rate, batch size, augmentation, β_CB, ω, etc.). Kendall's learned $\sigma$ automatically adapts every training step. The 3 extra scalar parameters ($s_d, s_p, s_a$) are negligible overhead compared to the 40M+ model parameters.</p>
  </div>
</div>
<div class="card" style="padding:0;overflow:hidden;margin-top:8px">
  <button class="accordion-toggle" onclick="toggleAccordion(this)">
    <span>Q: "Do σ values converge?"</span><span class="accordion-arrow">▸</span>
  </button>
  <div class="accordion-body">
    <p>Yes. In practice $s_d$ stabilizes around 0.3–0.5, $s_p$ around −0.8 to −1.2 (high weight for pose), $s_a$ around 0.1–0.3. The pose task maintains the <strong>highest precision</strong> (lowest $s_p$, highest $e^{-s_p}$) because accurate pose is a prerequisite for meaningful FiLM conditioning — the Kendall mechanism independently discovers this dependency structure from gradient signals alone. The convergence is smooth and monotonic after warmup, confirming the mechanism is well-behaved for our 3-task setup.</p>
  </div>

<h3>8h. Worst Case Without Kendall</h3>
<div class="card card-warn">
<h4 style="color:var(--orange)">With fixed weights λ₁=λ₂=λ₃=1.0:</h4>
<p>Detection loss values at initialization are typically 10–50× larger than Wing Loss values (different unit spaces). The total loss would be dominated by the detection term purely because of unit differences. Activity classification would effectively receive near-zero relative gradient. The model learns detection well but fails at activity recognition — the exact task we care most about. Any λ fix requires retuning when the dataset or any hyperparameter changes.</p>
</div>

<h4 style="margin-top:0">Why this matters for FiLM</h4>
<p>The FiLM module receives <strong>both</strong> keypoint coordinates (gradient-connected) and confidence values (computed under <code>torch.no_grad()</code> from heatmaps, then fed in as a plain tensor). Through the <strong>FiLM branch</strong>, gradients reach earlier layers only via the <strong>keypoint</strong> components of the 51D pose vector; the confidence buffer does not backpropagate into the backbone. <strong>Separately</strong>, the detection and pose heads still train the backbone on their own losses. This avoids a circular dependency where the backbone could chase &ldquo;confident-looking&rdquo; heatmaps instead of accurate localization.</p>

<h4 style="color:var(--gold)">Core Hypothesis</h4>
<p style="font-size:1.05rem; font-style:italic;">"Human pose geometry provides complementary information to visual features for assembly activity understanding. Explicitly conditioning deep visual features (FiLM on C5) on pose encoding is more effective than naively concatenating pose with visual features, because FiLM allows pose to modulate WHICH visual features are relevant for a given body configuration, rather than simply appending pose as additional input."</p>

<h3>Literature Search Result <span class="badge badge-claim prof-badge">KEY CLAIM</span></h3>
<p>A comprehensive literature search across skeleton-based action recognition, FiLM/CBN conditioning papers, and pose-guided video understanding (2014–2026) found <strong>no prior work</strong> that simultaneously satisfies all of: (1) task is action recognition, (2) conditioning signal is pose/skeleton/body keypoints, (3) mechanism is explicit FiLM-style affine modulation ($\gamma \cdot x + \beta$) applied to CNN feature maps where $\gamma, \beta$ come from pose features.</p>

<p>The closest related work is MMN (Gu et al., 2025), which applies FiLM-style modulation in the <em>skeleton feature space</em> for micro-action recognition — but it does not condition RGB/CNN features on pose. Our approach of using pose to modulate ResNet C5 features via FiLM for action recognition appears to be genuinely novel.</p>

<h3>Three Novel Contributions</h3>
<div class="card card-accent" style="margin-bottom:12px">
<p><strong>1. Pose-Conditioned FiLM on C5</strong> — First application of FiLM conditioning using body skeleton pose for assembly activity recognition. Unlike the original FiLM (language → VQA), we use pose geometry → activity classification via modulation of the deepest CNN features.</p>
</div>
<div class="card card-accent" style="margin-bottom:12px">
<p><strong>2. Wing Loss for Full-Body Keypoints</strong> — Extension of Wing Loss from facial landmarks (68 points, roughly 80px face region) to full body keypoints (17 COCO joints, 640×480 field) with adapted parameters (ω=0.05, ε=0.005 in normalized coordinates).</p>
</div>
<div class="card card-accent">
<p><strong>3. CB-Focal + Kendall for Assembly MTL</strong> — Unified treatment of class imbalance (CB), easy-sample dominance (Focal), and cross-scale multi-task optimization (Kendall) in a single training objective for 3-task assembly recognition.</p>
</div>

<h3>14b. CNN vs Transformer: Data Regime Crossover</h3>
<p>Vision Transformers lack the inductive biases (translation equivariance, local receptive fields) that allow CNNs to learn efficiently from small datasets. ViTs rely on learning spatial structure from data alone, requiring orders of magnitude more training samples to match CNN performance in low-data regimes.</p>

<p class="step-keyterm mono" style="font-size:0.82rem">Focus: <strong>γ = 1+tanh</strong> (bounded scale), <strong>β</strong> linear head</p>
<pre><code>gamma_raw = gamma_net(pose_flat)
          = Linear(51→512) → BN → ReLU → Linear(512→2048)

gamma = 1 + tanh(gamma_raw)      # range (0, 2)
  Example channels: [1.30, 0.17, 1.60, 0.90, ...]

beta = beta_net(pose_flat)        # unbounded
  Example channels: [0.05, -0.20, 0.15, 0.00, ...]</code></pre>
<p>The network has learned: for a "reaching forward" pose, amplify hand-object interaction channels (γ=1.60) and suppress background channels (γ=0.17). The <code>1+tanh</code> ensures γ stays in (0,2) — never negative, never inverts features.</p>

<div class="step-content" id="step5">
<h4>Step 6: FiLM Modulation on C5</h4>
<p class="step-keyterm mono" style="font-size:0.82rem">Focus: affine <strong>γ⊙C5 + β</strong> broadcast over spatial grid</p>
<pre><code>C5_mod = gamma.view(B,2048,1,1) * C5 + beta.view(B,2048,1,1)

Channel 3 (hand-object): γ=1.60, β=+0.15
  Before: activation mean = 0.55
  After:  0.55 × 1.60 + 0.15 = 1.03   ← +87% amplification

Channel 2 (background): γ=0.17, β=−0.20
  Before: activation mean = 0.375
  After:  0.375 × 0.17 + (−0.20) = −0.136  ← suppressed to near-zero

Result: C5_mod still [1, 2048, 20, 15] but now pose-aware.</code></pre>
<p>The feature map is transformed from a generic scene representation into a pose-conditioned representation that emphasizes hand-object interactions for this "insert dowel" configuration.</p>
</div>

<div class="step-content" id="step6">
<h4>Step 7: Activity Classification</h4>
<p class="step-keyterm mono" style="font-size:0.82rem">Focus: <strong>residual bottleneck</strong> + 33-way logits</p>
<pre><code>gap_c5  = GAP(C5_mod)              # [1, 2048]
gap_p4  = GAP(P4)                   # [1, 256]
feat    = cat(gap_c5, gap_p4)       # [1, 2304]

Residual bottleneck:
  x = Linear(2304→512)(feat) → BN → ReLU
  x = Linear(512→256)(x) → BN → ReLU
  x = Linear(256→512)(x) → BN → ReLU → Dropout(0.3)
  skip = Linear(2304→512)(feat)     # skip connection
  x = x + skip → BN → ReLU

logits = Linear(512→33)(x)          # [1, 33]
probs  = softmax(logits)
  → p("insert_dowel") = 0.71       # highest probability</code></pre>
</div>

<div class="step-content" id="step7">
<h4>Step 8: Wing Loss Computation</h4>
<p class="step-keyterm mono" style="font-size:0.82rem">Focus: log region gradient <strong>ω/(ε+|e|)</strong></p>
<pre><code>Predicted right wrist:  (0.703, 0.407)
Ground truth:           (0.700, 0.400)
Error: |Δx|=0.003, |Δy|=0.007, |e|=0.00762

Since |e| = 0.00762 < ω = 0.05 (log region):
  L_wing = ω · ln(1 + |e|/ε) = 0.05 · ln(1 + 0.00762/0.005)
         = 0.05 · ln(2.524) = 0.05 · 0.926 = 0.0463

Compare:
  L2 = 0.00762² = 0.0000581  (800× smaller — almost no signal!)
  L1 = 0.00762               (6× smaller)
  Wing gradient: ω/(ε+|e|) = 0.05/(0.005+0.00762) = 3.97</code></pre>
<p>Wing provides the <strong>strongest gradient</strong> for this small, precision-critical error.</p>
</div>

<div class="step-content" id="step8">
<h4>Step 9: CB-Focal Loss for Activity</h4>
<p class="step-keyterm mono" style="font-size:0.82rem">Focus: <strong>α<sub>c</sub></strong> rare-class up-weight × <strong>(1−p)<sup>γ</sup></strong></p>
<pre><code>True class: "insert_dowel" (n_c = 142 training samples)
Predicted:  p_y = 0.71

CB weight:
  α = (1 - 0.9999) / (1 - 0.9999^142) = 0.0001 / 0.01411 = 0.00709

Focal modulator:
  (1 - p_y)^γ = (1 - 0.71)^2.0 = 0.29² = 0.0841

CE term:
  -log(p_y) = -log(0.71) = 0.3425

CB-Focal loss:
  L_act = α · (1-p)^γ · (-log p)
        = 0.00709 × 0.0841 × 0.3425
        = 0.000204</code></pre>
<p>The focal factor reduces this moderately-confident prediction's loss by 12× compared to standard CB loss. Gradient capacity is freed for hard, uncertain samples.</p>
</div>

<div class="step-content" id="step9">
<h4>Step 10: Kendall Weighted Total Loss</h4>
<p class="step-keyterm mono" style="font-size:0.82rem">Focus: <strong>e<sup>−s</sup> · L + s</strong> homoscedastic rebalancing</p>
<pre><code>Current learned log-variance values (mid-training):
  s_d =  0.35 → weight = exp(-0.35) = 0.705
  s_p = -0.80 → weight = exp(0.80)  = 2.226
  s_a =  0.12 → weight = exp(-0.12) = 0.887

Task losses:
  L_det  = 0.423   (Focal + Smooth L1 for detection)
  L_pose = 0.0463  (Wing Loss, from Step 8)
  L_act  = 0.312   (CB-Focal, from Step 9 — aggregated batch)

Kendall total:
  L = e^{-s_d} · L_det + s_d  +  e^{-s_p} · L_pose + s_p  +  e^{-s_a} · L_act + s_a
    = 0.705 × 0.423 + 0.35     = 0.648  (detection)
    + 2.226 × 0.0463 + (-0.80) = -0.697 (pose — high weight!)
    + 0.887 × 0.312 + 0.12     = 0.397  (activity)
    = 0.348</code></pre>
<p>Pose gets 2.2× precision weight despite having the smallest raw loss — the Kendall mechanism has learned that pose accuracy is critical because it drives FiLM conditioning quality.</p>
</div>

<div class="step-content" id="step10">
<h4>Step 11: Backpropagation</h4>
<p class="step-keyterm mono" style="font-size:0.82rem">Focus: activity loss path through <strong>FiLM → C5</strong> (pose still supervises P4)</p>
<pre><code>loss.backward()   # Computes ∂L/∂θ for ALL parameters

Gradient pathways:
  L_det  → detection head → FPN → backbone          ✅
  L_pose → pose head → soft-argmax → FPN → backbone ✅
  L_act  → activity head → GAP(C5_mod) → FiLM → backbone ✅
           activity head → GAP(P4) → FPN → backbone       ✅

FiLM gradient chain:
  ∂L_act/∂C5 = ∂L_act/∂logits · ∂logits/∂gap · ∂gap/∂C5_mod · γ
  ∂L_act/∂γ  = ∂L_act/∂C5_mod · C5
  ∂L_act/∂β  = ∂L_act/∂C5_mod

Kendall σ update:
  ∂L/∂s_d = -e^{-s_d} · L_det + 1
  At equilibrium: e^{-s_d} · L_det ≈ 1  →  s_d ≈ log(L_det)</code></pre>
<p>All three loss pathways converge in the backbone, enabling unified feature learning. The Kendall $s_t$ parameters receive gradients that push them toward the natural log-loss scale of each task.</p>
</div>

<section id="limitations">
<h2><span class="sec-num">16</span> Limitations &amp; Future Work</h2>
<p class="subtitle">Honest scope boundaries for a professor defense</p>
<ul style="font-size:0.9rem;line-height:1.75;padding-left:1.2rem">
<li><strong>Single-frame RGB.</strong> No temporal model; motion blur and ambiguous phases (e.g. insert vs remove) hurt without video context.</li>
<li><strong>Pose from heatmaps.</strong> Keypoints are in-network soft-argmax, not an external HRNet/ViTPose — errors on occlusion propagate into FiLM.</li>
<li><strong>FiLM on strong baselines.</strong> Gains shrink when the backbone already encodes pose-correlated cues (§11b); ablations on improved3 remain the cleanest evidence for the mechanism.</li>
<li><strong>Metrics gap vs stronger temporal systems.</strong> Temporal and multimodal models reported in external surveys exceed our single-frame Top-1; our claim is architectural (pose-conditioned FiLM), not leaderboard records.</li>
<li><strong>Single-task heads not benchmarked.</strong> Joint training vs isolated heads was not fully swept; reserved as future ablation.</li>
<li><strong>Future:</strong> temporal adapter (lightweight TSM/X3D), ViT backbone at scale if video/frame budget grows, calibrated confusion exports on the full 33-way head, and hard-negative mining for dowel/bolt disambiguation.</li>
</ul>

// ===== Channel Grid Visualization (D1) — 16×16, deterministic base regions =====
function channelGridMulberry32(a) {
  return function() {
    var t = (a += 0x6d2b79f5);
    t = Math.imul(t ^ (t >>> 15), t | 1);
    t ^= t + Math.imul(t ^ (t >>> 7), t | 61);
    return ((t ^ (t >>> 14)) >>> 0) / 4294967296;
  };
}

function ensureChannelGridCells() {
  var grid = document.getElementById('channelGrid');
  if (!grid) return [];
  var existing = grid.querySelectorAll('.channel-box');
  if (existing.length === 256) return Array.prototype.slice.call(existing);
  grid.innerHTML = '';
  var cells = [];
  for (var i = 0; i < 256; i++) {
    var row = Math.floor(i / 16);
    var col = i % 16;
    var base = 0.6;
    /* Background (suppressed) */
    if (i <= 30) base = 0.10 + ((i % 7) * 0.03);
    /* Floor (suppressed) */
    else if (i <= 60) base = 0.15 + ((i % 6) * 0.03);
    /* Arm/wrist semantic groups (amplified) */
    else if ((i >= 180 && i <= 210) || (i >= 230 && i <= 255)) base = 0.85 + (((i * 13) % 100) / 100) * 0.9;
    /* Mid channels */
    else base = 0.40 + (((row + col) % 8) / 8) * 0.70;

    var cell = document.createElement('div');
    cell.className = 'channel-box channel-cell';
    cell.dataset.baseGamma = base.toFixed(4);
    cell.title = 'group ' + i + ' · base γ=' + base.toFixed(2);
    grid.appendChild(cell);
    cells.push(cell);
  }
  return cells;
}

    betaBar.style.left = b >= 0 ? '50%' : (50 - bw) + '%';
  }
  if (betaLbl) betaLbl.textContent = 'Aggregate shift visualization: β = ' + (b >= 0 ? '+' : '') + b.toFixed(2) + ' (bar length ∝ |β|)';

  var cells = ensureChannelGridCells();
  cells.forEach(function(cell, idx) {
    var base = parseFloat(cell.dataset.baseGamma || '0.6');
    var eff = Math.max(0, Math.min(2.5, base * g + b));

      cell.style.boxShadow = 'none';
      cell.style.borderColor = 'rgba(100,116,139,0.45)';

function wingLWing(ax, w, eps) {
  var C = w - w * Math.log(1 + w / eps);
  return ax < w ? w * Math.log(1 + ax / eps) : ax - C;
}

function wingGrad(ax, w, eps) {
  return ax < w ? w / (eps + ax) : 1;
}

// ===== Heatmap canvas + soft-argmax (sliders hmX / hmY) =====
function drawHeatmapSoftmax() {
  var canvas = document.getElementById('hmCanvas');
  if (!canvas || !canvas.getContext) return;
  var sx = document.getElementById('hmX');
  var sy = document.getElementById('hmY');
  if (!sx || !sy) return;
  var peakX = parseFloat(sx.value);
  var peakY = parseFloat(sy.value);
  var vx = document.getElementById('hmXVal');
  var vy = document.getElementById('hmYVal');
  if (vx) vx.textContent = String(Math.round(peakX));
  if (vy) vy.textContent = String(Math.round(peakY));

  var gw = 60;
  var gh = 40;
  var sigma = 4.5;
  var logits = [];
  var i, j, idx, dx, dy, v;
  for (j = 0; j < gh; j++) {
    for (i = 0; i < gw; i++) {
      dx = i - peakX;
      dy = j - peakY;
      v = -(dx * dx + dy * dy) / (2 * sigma * sigma);
      logits.push(v);
    }
  }
  var maxL = logits[0];
  for (idx = 1; idx < logits.length; idx++) {
    if (logits[idx] > maxL) maxL = logits[idx];
  }
  var expSum = 0;
  var probs = new Array(logits.length);
  for (idx = 0; idx < logits.length; idx++) {
    probs[idx] = Math.exp(logits[idx] - maxL);
    expSum += probs[idx];
  }
  for (idx = 0; idx < probs.length; idx++) {
    probs[idx] /= expSum;
  }
  var ex = 0;
  var ey = 0;
  idx = 0;
  for (j = 0; j < gh; j++) {
    for (i = 0; i < gw; i++) {
      ex += probs[idx] * i;
      ey += probs[idx] * j;
      idx++;
    }
  }

  var ctx = canvas.getContext('2d');
  var cw = canvas.width;
  var ch = canvas.height;
  var cellW = cw / gw;
  var cellH = ch / gh;
  var img = ctx.createImageData(cw, ch);
  var p, px, py, r, g, b, a, base;
  for (py = 0; py < ch; py++) {
    for (px = 0; px < cw; px++) {
      i = Math.min(gw - 1, Math.floor(px / cellW));
      j = Math.min(gh - 1, Math.floor(py / cellH));
      p = probs[j * gw + i];
      r = Math.round(15 + p * 220);
      g = Math.round(40 + p * 180);
      b = Math.round(80 + p * 200);
      a = 255;
      base = (py * cw + px) * 4;
      img.data[base] = r;
      img.data[base + 1] = g;
      img.data[base + 2] = b;
      img.data[base + 3] = a;
    }
  }
  ctx.putImageData(img, 0, 0);
  ctx.strokeStyle = '#fbbf24';
  ctx.lineWidth = 1.5;
  ctx.setLineDash([4, 3]);
  ctx.beginPath();
  ctx.arc(ex * cellW + cellW * 0.5, ey * cellH + cellH * 0.5, 4, 0, Math.PI * 2);
  ctx.stroke();
  ctx.setLineDash([]);

  var out = document.getElementById('hmSoftArgmax');
  if (out) {
    out.textContent = 'soft-argmax (x, y) = (' + ex.toFixed(2) + ', ' + ey.toFixed(2) + ')  —  matches Gaussian peak (' + peakX.toFixed(1) + ', ' + peakY.toFixed(1) + ')';
  }
}

    return;
  }
  var beta = 0.9999;
  var alpha = (1 - beta) / (1 - Math.pow(beta, nc));
  var effectiveN = (1 - Math.pow(beta, nc)) / (1 - beta);
  out.textContent = alpha.toFixed(5);
  if (expl) {
    expl.textContent = 'Cui et al. effective-number mass (1−β^{n_c})/(1−β) = ' + effectiveN.toFixed(2) +
      '. Inverse used in α_c = (1−β)/(1−β^{n_c}) = ' + alpha.toFixed(5) + '.';
  }
}

function initWingGradientChart() {
  var ctx = document.getElementById('wingGradientChart');
  if (!ctx || typeof Chart === 'undefined') return;
  destroyChartIfAny(ctx);
  try {
    var w = 0.05, eps = 0.005, delta = 0.01;
    var xs = [];
    var si;
    for (si = -120; si <= 120; si++) xs.push(si * 0.001);
    function gradL2(x) { return 2 * x; }
    function gradL1(x) { return Math.abs(x) < 1e-14 ? 0 : Math.sign(x); }
    function gradHuber(x) {
      var ax = Math.abs(x);
      return ax <= delta ? x : delta * Math.sign(x);
    }
    function gradWingSigned(x) {
      var ax = Math.abs(x);
      if (ax < 1e-14) return 0;
