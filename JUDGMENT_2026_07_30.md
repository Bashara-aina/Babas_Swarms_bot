### Disagreements and Nuances
1. **Single-recording bug** (B4): Agent 4 rates this CRITICAL. But the actual v3.49 training launch script uses the full `recordings/train/` directory, not `01_main_0_1`. The hardcoded path at `train_mtl_full_multimodal.py:881` is only a fallback default that modern launch scripts override. **Rerating: MEDIUM** -- genuine risk for ad-hoc use, but not the cause of current regression.

2. **ACT verb grouping**: Agent 2 recommends switching to 13-verb grouping. The synthesis agrees. But the v3.49 launch script deliberately uses `unset ACT_CLASS_GROUPING` (75-class raw). Reason: earlier attempts with verb grouping caused silent head resets. **The correct fix is hierarchical** -- train the head on 75 classes with balanced loss, then *eval* with verb-grouped projection. Not a raw head-size reduction.

3. **eval_real_mAP.py vs eval_real_map_fast.py**: Agent 1 declares `eval_real_mAP.py` CORRECT and the canonical eval. But this script exists in the root directory, not in `scripts/eval/`. The actual eval pipeline used for reported numbers is `eval_v3.34_psr_sweep_v3.48.py` and `eval_all_heads.py`. **Multiple canonical evals** is the root problem -- need a single entry point.

4. **Achievement-MTL update_kpi()**: Synthesis says "NEVER called" but the launch script comment says it IS called. Training log shows ach_w DID change from initial `[0.29, 0.31, 0.20, 0.20]` to `[0.36, 0.35, 0.14, 0.14]`. The mechanism works but weights plateau because activity loss never converges. **The fix is the loss function, not the balancer.**

### P1: FIX ACT TRAINING COLLAPSE

#### P1-A: Switch activity loss to BalancedSoftmax (post-hoc formulation)
**Rationale**: The training log shows act_loss stays 0.8-5.3 (never below 0.8). For a 75-class task, CE should converge toward 0 for learned classes. The current `LogitAdjustedCELoss` (tau=1.5) trains with logit shift, which can destabilize the early training. The post-hoc formulation (`BalancedSoftmaxLoss`) uses standard CE during training and applies logit adjustment only at inference.

**File:** `${BASE}/scripts/train/train_mtl_v3_yolov8_head.py`
- **L381-397:** Change from `LogitAdjustedCELoss` to `BalancedSoftmaxLoss` as default
- **L1066-1087:** Ensure the `balanced_act_loss_fn` branch is the primary path
- **L1178:** Verify `act_loss` is weighted correctly in total loss

**File:** `${BASE}/runs/mtl_v3.49_proper/launch_v3.49.sh`
- Change `--use-logit-adjust-act --logit-adjust-tau 1.5` to `--use-balanced-softmax-act --act-logit-adjust-tau 2.0`

#### P1-B: Increase activity learning rate
**Rationale**: Current `--act-lr-mult 20` gives effective LR = `1e-5 * 20 = 2e-4`. For a randomly initialized head being trained alongside a pretrained backbone, this may be too low. The frozen probe achieves 38.1%, which shows the backbone features ARE discriminative -- the head just isn't converging.

**File:** `${BASE}/runs/mtl_v3.49_proper/launch_v3.49.sh`
- Change `--act-lr-mult 20` to `--act-lr-mult 50` (effective LR = 5e-4)

#### P1-C: Add verb-grouped evaluation (not training)
**Rationale**: Training with 75 classes is correct (matches the evaluation). But reporting 75-class accuracy on a dataset where 48/75 classes have <10 frames is misleading. Use `_build_act_grouping('verb')` to project predictions to ~13 verb groups for a meaningful secondary metric.

**File:** `${BASE}/scripts/eval/eval_v4_standard.py`
- Add `--act-grouping {none,verb,hybrid}` flag
- When set to `verb` or `hybrid`, compute verb-grouped top-1 in addition to raw 75-class
- The verb group mapping already exists at `config.py L488-552`

## 5. Decision: PROCEED

**Consensus is strong enough.** The disagreements identified above are all resolvable nuances, not fundamental strategy conflicts. The core narrative is clear:

| Problem | Root Cause | Fix Priority |
|---------|-----------|-------------|
| Untrustworthy metrics | 3+ eval scripts with different anchor configs | P0 (eval standardization) |
| ACT 1.2% raw top-1 | Training collapse + wrong loss function | P1 (BalancedSoftmax + LR) |
| PSR event F1 ~0 | Per-frame MLP head, no temporal context | P2 (wire PSRTransitionPredictor) |
| DET stuck at 0.27 | Under-trained + noisy ACT head destabilizes backbone | P3 (fixes + more epochs) |
| No regression tracking | Manual eval, no benchmark infrastructure | P4 (automation) |

### Risk Assessment
| Risk | Likelihood | Mitigation |
|------|-----------|-----------|
| PSRTransitionPredictor training destabilizes PSR per-frame F1 | Medium | Keep PSRHead as fallback; train with `--psr-head mlp` fallback |
| BalancedSoftmax doesn't fix ACT collapse | Medium | Try verb-grouped hierarchical head next |
| ACT LR increase causes backbone forgetting | Low | Only the head parameters get higher LR (via parameter groups at L897) |
| Eval standardization reveals worse numbers than reported | Low | Required for honest progress tracking |
| Breaking existing checkpoint loading | Medium | P2-A adds new head, old checkpoints won't have `psr_predictor` weights -- use `strict=False` and initialize randomly with warning |

### Verdict: PROCEED

Begin immediately with **Workstream A** (eval standardization + ACT fix). This can be done in 2-3 days and will produce the first measurable improvement (ACT raw top-1 going from 1.2% to >15%). Start **Workstream C** (DET decode fixes) in parallel since it's independent and low-risk.

Start **Workstream B** (PSR temporal) only after P0-A is verified and the ACT fix is stable -- this is the highest-risk change and should not block the quicker wins.

**Immediate next step:** Create `scripts/eval/eval_v4_standard.py` and run on all 3 existing checkpoints to establish the honest baseline before any model changes.
